# BANKING77 intent decisions and retrieval-agent escalation

## Research question

Can a typed System One decision replace some invocations of a retrieval-using agent on a closed-set intent task, reducing observed cost while preserving classification quality? This is Rami’s separate original-proposal workstream; it complements the team’s repository-localization studies without pooling their unlike accuracy measures.

## Environment and data

We use the official 77-intent BANKING77 data at PolyAI-LDN/task-specific-datasets revision `57ec275d8078af65b7731c2a98be812d844a6d6b` (10,003 training and 3,080 test utterances; CC BY 4.0). Canonical category strings are evaluator labels. The three source files total 1,081,070 bytes. UTF-8 SHA-256 receipts are in `intent_frozen.json`. Training utterances are grouped by NFKC-normalized, case-folded alphanumeric tokens before seeded partitioning, so a normalized group cannot cross the support/development/certification boundary. The resulting counts are 7,039 / 1,500 / 1,464. One cross-label normalized group is retained and disclosed. All official test rows are retained; a secondary analysis excludes normalized support overlap. Public benchmark pretraining contamination cannot be ruled out.

The catalog includes all 77 canonical labels, descriptions obtained by replacing underscores with spaces, and one deterministic real support exemplar per intent. Jev and the direct baseline receive the same fixed label descriptions and exemplars. The retrieval index contains only support cases. Gold test labels and held-out examples are unavailable to the model tools.

## Methods

Jev (`typesafe/jev-1.14`, canonical catalog revision `typesafe/jev-1.14-20261014`) answers a typed 77-way Choice through OpenRouter’s Decisions API. The gate uses the largest returned class probability, not the vendor’s separate distribution-concentration confidence statistic. All 77 entries, finite probability ranges, normalization and selected argmax are validated. Invalid decisions escalate; attempted cost remains in accounting.

The strong model is `openai/gpt-6.1-sol` (canonical catalog revision `openai/gpt-6.1-sol-20260929`). The direct condition makes one classification call. The tool-using condition runs OpenCode 1.19.5’s native agent loop, with a support-only BM25 search tool and an intent lookup tool. At least one real search is required; final outputs must contain a canonical intent and support IDs returned by the tools. The agent receives no Jev prediction or confidence, which makes its saved trajectory reusable for confidence-based and random-route counterfactuals. Filesystem, shell, web, and delegation tools are disabled.

Caps are four generative requests, two retrieval calls returning at most eight search examples, 1,024 output tokens/request, 120 seconds/task and $0.25/task. The parent adapter forces the pinned model and records each upstream request, response, usage/cost receipt and retrieval result. Two persistent native server processes have isolated state and up to six independent fresh sessions each; no session memory is reused. Explicit titles suppress an irrelevant automatic conversation-title call. Session messages are saved before deletion. A shared SQLite ledger atomically reserves spend before concurrent API calls. The overall experiment cap is $120. Only HTTP 429 receives up to two explicit retries; other attempted requests remain visible, with unknown costs conservatively reserved.

Development chooses one threshold from 0.50–1.00 to maximize coverage subject to empirical accepted error <=3% and at least 100 accepted cases. The selected threshold is 0.96. Independent certification accepted 872/1,464 examples with 34 errors. The one-sided 95% Clopper–Pearson upper bound is 5.157%, so certification against the proposed 5% target failed. No threshold was adjusted on certification. No positive-coverage Jev policy was certified. The predeclared default fallback uses no Jev decisions (effective threshold 1.01); this does not certify the agent’s own error rate. A published pre-test continuation amendment retains the original 0.96 candidate as an uncertified comparison, within the authorized full experiment and original budget. This is a negative certification finding, not a guarantee.

All 3,080 official test IDs, source fingerprints, prompts, model metadata, thresholds and analysis seeds were committed before any test model queries. One Jev decision, one strong-direct prediction and one native retrieval-agent trajectory are collected for every test example. The primary certified fallback always escalates and includes Jev overhead. The separate fixed candidate accepts Jev at 0.96 and otherwise uses the identical fallback. Twenty fixed random seeds accept exactly as many valid Jev predictions as this candidate, without looking at confidence, and otherwise use the same agent. An optional zero-inference-cost nearest-example reference is reported separately. No routing comparator triggers duplicate paid test trajectories.

## Evaluation and accounting

Exact intent match determines correctness. Every frozen example remains in the denominator; malformed outputs, missing retrieval/citations, timeouts and service errors are incorrect. We report accuracy, macro-F1, Jev coverage and accepted error, observed cost/query and cost/correct prediction, model/tool calls, calibration, corrections/regressions, confusions and overlap sensitivity. Two thousand paired intent-stratified bootstrap replicates estimate accuracy differences and cost ratios against the agent. The prespecified accuracy target is a one-sided 95% lower difference bound above -2 percentage points. A result against that target cannot undo failed independent risk certification. Binomial interpretations require independence/exchangeability assumptions that this stratified public benchmark may only approximate.

Deployment costs count the calls selected by a policy, including Jev overhead and actual fallback cost. Research spending separately includes every baseline, development, certification, engineering diagnostic and unresolved reservation. Reasoning/cache charges are taken from provider receipts. Recorded parallel per-task times include load/queue effects; offline routed sums are replay estimates. A separate serial 12-example development check measures the certified fallback’s live orchestration latency after warming the native runtime without paid calls.

## Safety, reproducibility and authorship

The system predicts public benchmark intent labels and retrieves public support examples. It cannot perform banking transactions. This study does not evaluate unknown intents, adversarial robustness, production finance use, or private customer data. Only local proxy tokens enter native processes; the upstream key stays in the parent and is excluded from source, model inputs and artifacts. Model calls were explicitly authorized and capped. No Tinker training was used.

Source, pinned data receipts, frozen test IDs, raw model/tool traces and accounting exports are archived for offline reconstruction. New live model runs may vary; reported metrics are reproduced from saved trajectories. Rami selected and directed this individual workstream; Codex implemented and ran the experiment and drafted this text. Team review is required before incorporation into the final paper. No report/video submission or merge to main was performed.
